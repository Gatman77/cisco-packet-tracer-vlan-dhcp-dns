В этом проекте я собрал и настроил небольшую компьютерную сеть в Cisco Packet Tracer. Хотел разобраться, как на практике работают VLAN, маршрутизация между сетями, DHCP и DNS.
Выполненные задачи
- Разделил устройства на несколько VLAN, чтобы они находились в разных сетях.
- Настроил multilayer switch, который выполняет маршрутизацию между VLAN.
- Настроил DHCP-сервер, чтобы компьютеры автоматически получали IP-адреса.
- Добавил DHCP relay, чтобы запросы на получение адреса доходили до сервера из разных VLAN.
- Настроил отдельный DNS-сервер для проверки работы разрешения имён.
- Проверил, что устройства получают настройки сети и могут обращаться к нужным серверам.
В сети есть четыре VLAN для клиентских устройств и отдельная VLAN для серверов.

VLAN 10 - 192.168.10.0/24 - 192.168.10.1(Шлюз по умолчанию)
VLAN 20 - 192.168.20.0/24 - 192.168.20.1
VLAN 30 - 192.168.30.0/24 - 192.168.30.1
VLAN 40 - 192.168.40.0/24 - 192.168.40.1
VLAN 100 - 192.168.100.0/24 - 192.168.100.1

Для серверов выделена отдельная сеть:
- DHCP-сервер: 192.168.100.10
- DNS-сервер: 192.168.100.11
Когда компьютер подключается к сети, он получает IP-адрес и остальные сетевые настройки от DHCP-сервера. Для этого на multilayer switch настроен DHCP relay, который передаёт запросы из клиентских VLAN на сервер.
У каждой VLAN своя подсеть и свой шлюз. При этом multilayer switch позволяет устройствам из разных VLAN обмениваться данными, если это разрешено настройками сети.
DNS-сервер нужен для того, чтобы проверять работу доменных имён. Например, можно создать запись и связать имя с IP-адресом.
В итоге получилось разделить сеть на несколько VLAN, настроить автоматическую выдачу IP-адресов и DNS, а также маршрутизацию между подсетями.
Для меня это практика по основным сетевым настройкам Cisco. В процессе пришлось проверять конфигурацию и искать ошибки, например, когда компьютеры получали неправильный DNS-адрес. Это помогло лучше понять, как отдельные части сети работают вместе.
